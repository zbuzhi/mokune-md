# 0.1.0 在线更新接入与验证

2026-10-27。首个公开版本为 0.1.0，内部构建号 30；历史 0.17.x 是开发记录，未带更新器的旧本地 App 需要手动安装一次。

## 已接入

- 固定 Sparkle 2.10.1 官方分发与 SHA256，完整保留主许可及 BSD/Zlib 等嵌入声明。框架约 2.9 MiB，实际压缩包增量依归档结果而定。
- 原生应用菜单“检查更新…”、“自动检查更新”。默认不自动检查、不自动下载/安装，不发送系统分析报告。
- 稳定 HTTPS feed 为 `https://raw.githubusercontent.com/zbuzhi/mokune-md/main/updates/appcast.xml`；下载包使用 GitHub Releases。空 feed 已签名，不发布任何安装项。
- 用户明确授权后创建独立 Ed25519 密钥，私钥仅在维护者 macOS 钥匙串 `mokune-md.zbuzhi` 账户。源码/应用只有公钥；从未导出或上传私钥。克隆者无需私钥即可编译和验签，fork 自行发行时必须更换自己的 feed、公钥和发行身份。
- 强制验签更新清单，下载包在解包前验证；不在配置中允许 HTTP。Git 保留签名 XML 的精确字节，CI 使用 Node 标准加密库和公钥验签，不接触私钥。
- 接入 NSApplication 的异步终止答复：等待编辑器同步所有标签，处理未保存文稿，原子写入会话后才允许退出。取消、组合输入或写入失败会拒绝终止。原生/网页组合状态短暂不同步也会取消，不无限等待退出答复。
- `prepare-update.mjs` 默认仅打印计划。明确执行仍需通过正式二进制检查和公证，才在本地创建签名归档/清单/哈希；不会上传或修改线上 feed。

## 实际验证

1. 132 项逻辑测试通过，包括更新配置约束、框架内部 symlink 与逃逸拒绝。
2. 从无 node_modules/dist 的隔离源码副本冻结安装，实际编译 arm64 和 x86_64，再合并通用 App；链接 Sparkle、原稿 MD7 图标及本地签名验证通过。没有替换正在使用的 App。
3. 原生退出测试五种情形通过：干净文稿异步终止、未保存修改取消、系统组合输入保护、网页组合标志领先于原生时取消、会话写入失败取消。真实配置的 Sparkle 控制器及两个菜单均能启动；原文与标签保持。
4. Sparkle 实际运行测试六种情形通过：签名空 feed、网络 404、篡改 feed、篡改安装包、取消安装、签名更新安装并重新启动。最终确认独立合成 App 从 build 30 替换为 build 31，且终止前的会话标记仍在；取消则维持 build 30。
5. 上述更新运行测试仅在 `.build` 中使用独立 App、独立 bundle ID 与回环 HTTP 服务器，HTTP/ATS 例外只存在于合成测试 App。正式 App 不含这些例外。测试没有上传二进制或操作个人文稿。
6. 回归独立标签/会话恢复、中文插入撤销、链接移动维护及正常退出通过。发布 smoke：浏览器预览与导出、原生文件 23、原生 WebKit 21、实际 PDF 7 份通过。本轮未新增实体输入法候选窗/Intel 硬件/旧 macOS 验收。

测试中修正了两个驱动判断：需要从编辑器快照读取最新未保存文本；需要等更新引擎确认取消，再结束测试进程。Sparkle 的“解包阶段”UI 回调先于最终验证结果，不能用它声称归档已经通过验证；篡改测试以签名错误码及未进入安装就绪状态、磁盘版本不变为依据。

源码公开前逐项清单检查还排除了曾被素材白名单包含的 `.DS_Store`，不删除本机原文件；同时将根 THIRD_PARTY_NOTICES.md 加入必需源码文件，确保 GitHub 上的许可链接及源码快照完整。

## 发行边界

这证明更新集成和本机合成 App 的完整链路可工作，不代表已经完成真实 Mokune 公证发行版之间的线上升级验收。公开二进制仍需 ELK 来源核验、权利与品牌复核、稳定发行身份、Developer ID、公证及实际发行包升级检查。源码公开不自动发布安装包；初始 feed 为空，因此当前检查只应提示没有可用更新。

私钥不要复制进 GitHub、日志、聊天或安装包。设备丢失/密钥泄露时需评估暂停更新和密钥轮换；没有密钥恢复备份或有效轮换路径时，可能需要用户手动重新安装。
